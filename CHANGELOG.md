- **2026-08-05** · **v9.7.4**: Content-Security-Policy added via `<meta http-equiv>` in `index.html` — the only delivery path on GitHub Pages, which sets no response headers, so there is no `frame-ancestors`/`report-uri`. `connect-src`/`img-src` derived from `js/api.js` and `js/seed.js`'s real fetch/image origins. Two real footguns found and fixed, not just papered over: `js/app.js`'s `haptic()` used `style.cssText` (blocked under `style-src` without `'unsafe-inline'`); `js/core.js`'s `badgeHtml()` built `onload=`/`onerror=` as literal HTML attributes on an innerHTML'd `<img>` (blocked under `script-src` with no `'unsafe-inline'`, even though the handlers are JS-authored, not markup-authored) — replaced with two capture-phase `document` listeners keyed off the `.blogo` class. `js/tappable.js`'s JS-injected `<style>` tag moved to a static rule in `css/components.css` instead of granting `style-src-elem 'unsafe-inline'`. `style-src-attr 'unsafe-inline'` is still required and kept: ~82 sites across portfolio.js/insights.js/explore.js/sheets.js compute per-render inline `style=""` (bar widths, hash-derived badge gradients) that neither a nonce nor a CSP hash can cover, since the values differ every render. Verified empirically — zero `securitypolicyviolation` events across Home, Markets (search + stock sheet), Portfolio (holding-detail sheet), Insights (module sheet), theme toggle, and both demo-mode and real-passcode unlock/setup flows, including the WebAuthn/Face ID enrollment prompt. No financial maths touched.
- **2026-08-05** · **v9.7.5**: session close-out — C-1 fixed: `js/vault.js`'s `#unlockPass`, `#setPass1`/`#setPass2` and `#restorePass` now clear on the success path too (previously only on failure), so a real unlock no longer leaves the plaintext passcode sitting in the live DOM for the rest of the tab's life; verified empirically against a real (non-demo) unlock, not by reading the code. `js/insights.js`'s `renderCoach()` now `esc()`s `x.title`/`x.detail` before they reach `innerHTML` — local-only today, defence-in-depth.
